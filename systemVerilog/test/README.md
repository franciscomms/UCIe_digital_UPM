# Regression tests

From the `systemVerilog` directory, with Verilator 5.x, a C++20 compiler,
GNU make, and Python 3 installed:

```sh
./scripts/run_tests.sh
./scripts/run_tests.sh --integration
./scripts/run_tests.sh UcieCodeWidthSpec_tb
./scripts/run_tests.sh JtagTapIntegrationSpec_tb
./scripts/run_tests.sh D2DAdapterLinkMgmtLtsmDualDieBringUpSpec_tb --parameter TEST_MODE_DIGITAL=1
```

Set `VERILATOR=/absolute/path/to/verilator` to choose another executable.
`--jobs N` controls C++ compilation parallelism; `--timeout N` limits each
simulation in seconds. Compile commands, diagnostics and simulation output
are saved in `build/<test>/command.txt`, `compile.log` and `run.log`.
The script returns nonzero if compilation or any self-check fails. It enables
assertions and checks that `docs/jtag_scan_map.json` matches the RTL. Compiler
warnings remain in the logs; a passing simulation is not lint or CDC signoff.

| `TrainingRestartSpec_tb` | Three TXSELFCAL/RXCLKCAL exchanges and analog calibrations without reset. |

Test mode: the test plays the partner die on `jtagLtsm_sb_rx_*` and drives the LTSM RESET, SBINIT, MBINIT; then every `jtagLtsm_*` input at 1 for 10 cycles, each LTSM input checked all-ones; then back to normal mode under reset. | `JtagTapIntegrationSpec_tb` | Supplied TAP connected to the real wrapper through an explicitly test-only decoder; all five banks, actual supplied SNAP/STEP opcodes, and new speed fields. |

The width test forces only the MBTrain output boundary to walk each physical
bit through the downstream wiring and packed scan fields. It does not claim
that a walking-one pattern is a legal analog code, and does not replace the
separate encoding/sweep tests or serial JTAG tests. Unused inputs are omitted
deliberately in this wiring-only test; `-Wno-PINMISSING` suppresses those
intentional omissions. Functional state-machine behavior is tested separately.

`--integration` also runs the three supplied full-link testbenches:

- `D2DAdapterLinkMgmtLtsmDualDieBringUpSpec_tb`
- `D2DAdapterLinkMgmtLtsmDualDieBackpressureSpec_tb`
- `D2DAdapterLinkMgmtTopIntegrated128Spec_tb`

The earlier broader `Integrated128` regression still reports unexpected
repeated requests on Disabled/LinkReset exits. Its checks are retained and
`--integration` therefore returns nonzero. Retrain and LinkError pass when
selected individually. See `docs/test_results.txt` and `docs/REVIEW.md` for the
exact failures and scope; the focused width/JTAG suite passes independently.

The Integrated128 training budget is now configurable and defaults to
12,000,000 cycles, matching the serial dual-die bench. The earlier baseline bring-up took
1,791,253 cycles, exceeding the former 1,500,000-cycle testbench timeout.

For commercial simulators, `rtl.f` lists packages before modules. Compile that
list, then the desired testbench and any supporting harnesses. The supplied
full-link benches additionally need `D2DAdapterLinkMgmtLtsmDualDieHarness.sv`
before other harnesses because it contains the analog-decode package. JTAG
integration additionally needs the simulation support package, inverter and
supplied TAP under `test/support/`. These test-only definitions do not replace
the production chip configuration, technology inverter, or bank decoder.

## Optional external golden-reference comparison

The original `DllPiEncodingSpec_tb` required a `dll_pi_control` module absent
from the uploaded archive. It is preserved, with only its module name changed,
as `reference/DllPiExternalReferenceSpec_tb.sv`. The default test is now a
self-contained physical-contract check, not an independent analog RTL model.
If the original `dll_pi_control` source is available, compile it with
`src/Parameters.sv` and the preserved test, selecting
`DllPiExternalReferenceSpec_tb` as the simulation top. That optional test checks
272 reference commands, production encodings and invalid-command hold behavior.

## Full serial speed fallback

`D2DAdapterLinkMgmtLtsmDualDieBringUpSpec_tb` accepts:

- `LINK_SPEED_FAIL_TOP_RATE_MASK=1`: fail one die at code 3; both must use 3→2→Active.
- `LINK_SPEED_FAIL_TOP_RATE_MASK=3`: fail both dies at code 3; the same expected rate sequence.
- Add `LINK_SPEED_FAIL_ALL_RATES=1`: fail each attempted rate; both must use 3→2→1→0→TRAINERROR.

The behavioral PHY delays speed acknowledgement and checks stable code/electrical
idle. Fault injection changes receiver comparison results only. The tests check
apply counts, rate-specific LINKSPEED visits, premature Active/error, terminal
rate retention and serial drain. Default parameters retain normal bring-up.
See `docs/test_results.txt` for the current executed results and commands.
